### Worktree and simulator cleanup

1. Snapshot e auditoria. Registre `df -h /`, depois rode `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Sem `-b` ele checa `MERGED` contra `origin/HEAD`, então passe `-b origin/<branch>` quando as PRs miram outro branch. Ele lê caminhos de `git worktree list`, nunca digitados à mão, já que um `myrepo-worktrees/x` digitado à mão perde um que vive em `.cursor/worktrees/myrepo/x` (principle-encode-lessons-in-structure). Ele classifica cada worktree por tamanho, idade, estado de merge, trabalho não commitado, estado de PR, e o chat mais recente que o tocou, depois sugere um balde. A varredura de transcrições é lenta, então rode em background.
2. O balde é conselho, não permissão. Os chats fixados e ativos são o artefato real (principle-prove-it-works). Pegue esse conjunto com o usuário ou na barra lateral e cruze cada candidato. A alavanca já marcou como `safe` um worktree que o usuário tinha fixado, então o conjunto de fixados vence.
3. Verifique o uso antes de apagar. Para toda linha `verify-recent-chat`, ou qualquer coisa que você duvide, espalhe subagentes para ler as transcrições e relatar se o chat está fixado ou em andamento e quais worktrees ele toca (principle-guard-the-context-window, transcrições são volume). Um chat fixado cria árvores de arena e de reprodução em worktrees irmãos via subagentes em background, e essas estão em uso mesmo quando os nomes nunca aparecem na barra lateral. Escolha o nível de raciocínio de cada subagente para o trabalho, conforme a seção Subagentes.
4. Pare em perda irreversível. `wip:N` são N edições rastreadas não commitadas. Mostre o diff e peça uma decisão primeiro, já que remover um worktree limpo é recuperável pelo branch mas trabalho não commitado some. `scratch:N` é descartável não rastreado, seguro de largar, mas nomeie os arquivos. Conforme Autonomia, limpo e mergeado e fora de uso segue. `wip` e em uso param.
5. Pode o conjunto confirmado. Por caminho, `git worktree remove --force <path>`. Se o diretório sobrevive em artefatos de build ignorados, `rm -rf` nele, depois `git worktree prune`. As refs de branch sobrevivem, então nenhum commit se perde. Confirme com `df -h /` e liste de novo.
6. Simuladores e outros reclaimers. Simuladores costumam ser o próximo maior ganho. `xcrun simctl --set testing delete all` (clones de XCTestDevices), `xcrun simctl delete unavailable`, e `xcrun simctl runtime list` depois `runtime delete <id>` para runtimes antigos. Mais quando precisar: `DerivedData` do Xcode e `iOS DeviceSupport`, `~/Library/Application Support/Cursor` (`state.vscdb.backup`, e `snapshots/roots/<root>` onde um `<root>` com nome de pasta que você abriu como workspace infla), caches de pacote (pnpm, uv, brew, yarn). Limpe só caches que o usuário não disse para manter.

Este é o único playbook que apaga estado do usuário sem revisão de código para pegar um deslize, então os portões acima são a revisão.

**Resposta:** `df -h /` antes e depois com espaço recuperado, os worktrees podados, e um motivo de uma linha para cada um segurado (em uso por qual chat, ou trabalho não commitado).
