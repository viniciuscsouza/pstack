# Experiência Primeiro

Quando a conveniência de implementação conflita com o encanto do usuário, escolha o encanto.

- Toda funcionalidade, controle e opção precisa se justificar
- Entregue menos, entregue melhor (experiência polida com três funcionalidades vence uma crua com dez)
- Prototipe antes de se comprometer (decisões de design saem mais baratas em HTML descartável do que em código de produção)
- Acerte os detalhes (transições, alinhamento, espaçamento, feedback, estados de erro)
- Aperte o laço central (toda funcionalidade deve servir ao fluxo central ou sair do caminho)

O usuário é quem consome o trabalho. Para uma UI é o usuário final. Para uma biblioteca ou uma API interna é o colega que a importa. O engenheiro que mantém o código depois também é usuário. Pese a experiência dele do mesmo jeito, e explique o impacto pela perspectiva dele.

As fundações devem servir à experiência. O pensamento fundacional governa a *sequência* do trabalho. Este princípio governa o *alvo*.
